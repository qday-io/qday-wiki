# 支付協定

QDAY2 支付協定定義了結構化、可驗證支付的生命週期。

**支付會話（Payment Session）** — 當付款方建立一筆鏈上支付意圖時，支付會話即啟動，其中指定：收款方地址、金額、幣別、到期時間，以及選填的中繼資料雜湊。會話 ID 由這些參數衍生而來。

**發票生命週期（Invoice Lifecycle）** — 發票會經歷以下狀態：`Created` → `Pending`（付款方已確認）→ `Paid`（資金已鎖定）→ `Settled`（資金已釋放給商家）→ `Expired`（逾時未付款）或 `Cancelled`（由付款方明確取消）。每次狀態轉換都會發出事件。

**結算最終性（Settlement Finality）** — 支付結算以 L2 批次最終性為前提。只有在包含該支付交易的批次通過 ZK 驗證後，資金才會釋放給商家。針對時效性較高的使用情境，可採用軟確認結算，並可設定確認門檻。

**串流支付（Streaming Payment）** — 串流支付依據流率（每秒代幣數）隨時間持續滴注資金。付款方鎖定一筆存款；收款方可隨時領取已累積的資金。若存款耗盡，串流會自動停止。

**Agent 支付授權（Agent Payment Authorization）** — AI Agent 透過限定於 Payment 合約範圍的會話金鑰（Session Key）發起支付。Agent 的會話金鑰指定：單筆支付金額上限、每期累計消費上限、允許的收款地址（白名單），以及到期時間。超出這些範圍的支付會在驗證階段被 EntryPoint 拒絕。
