# Docs authoring guide

This repo is the QDay Wiki ([community.qday.io](https://community.qday.io)), built with **Docusaurus**. The sidebar is **generated from the `docs/` folder**, so you usually do not need to edit `sidebars.ts`.

For the GitHub web-UI workflow aimed at PMs / ops, see [CONTENT-GUIDE.md](./CONTENT-GUIDE.md). This guide covers adding pages, nested sidebar categories, `_category_.json`, and how English and Chinese are maintained separately.

---

## 1. Directory map

| Path | Role |
|---|---|
| `docs/` | **English** source (default locale) |
| `i18n/zh-Hant/docusaurus-plugin-content-docs/current/` | **Traditional Chinese** source; folder layout must match `docs/` |
| `docs/<section>/_category_.json` | Sidebar label, order, and collapsed state for that folder |
| `static/` | Static files copied to the site root. `static/qday/foo.png` is served at `/qday/foo.png` |
| `data/updates.json` | Homepage “Latest updates” strip |
| `src/components/QDay/` | Interactive widgets you can embed in docs (add-network, faucet, etc.) |

Current top-level sections (folders under `docs/`):

```
docs/
  intro.md           Overview (a single page, not a folder)
  start/             Get Started
  guide/             User Guide
  migration/         Migration
  reference/         Reference
  dev/               Developers
  faq/               FAQ
  user/              User Documentation
  technical/         Technical Documentation
```

Page URLs follow the file path, for example:

- `docs/guide/metamask.mdx` → `/docs/guide/metamask`
- `docs/start/add-network.mdx` → `/docs/start/add-network`

## 2. Add a page

### 2.1 Pick a folder and filename

1. Put the file in the matching section, e.g. user guides: `docs/guide/`.
2. Use **lowercase kebab-case** names, e.g. `my-new-page.md`.
3. Use `.md` for ordinary docs. Use `.mdx` when you need to embed a React component (see section 6).

### 2.2 Frontmatter

Every file should start with a YAML header:

```markdown
---
sidebar_position: 5
title: My New Page Title
---

# My New Page Title

Start writing here…
```

Common fields:

| Field | Required | Meaning |
|---|---|---|
| `title` | Recommended | Page title. If omitted, the first `#` heading is used |
| `sidebar_position` | Recommended | Order among siblings; **smaller numbers appear first** |
| `sidebar_label` | Optional | Sidebar display name. If omitted, `title` is used |
| `slug` | Optional | Custom URL. Use this to keep the old path after moving a file |
| `description` | Optional | SEO / search snippet |
| `draft` | Optional | `true` hides the page from the production build |

### 2.3 The sidebar updates automatically

`sidebars.ts` is configured as:

```ts
tutorialSidebar: [{type: 'autogenerated', dirName: '.'}]
```

So **any new file under `docs/` shows up in the sidebar**. You do not need to change TypeScript.

## 3. Top-level vs nested categories

Sidebar depth follows folder depth.

```
docs/
  guide/                          ← top-level category “User Guide”
    _category_.json
    index.md
    metamask.mdx                  ← page directly under the top-level category
    wallets/                      ← nested category
      _category_.json
      metamask.mdx
      abelian-mobile-wallet.mdx
    staking/                      ← another nested category
      _category_.json
      qday-staking.mdx
      abel-staking.mdx
```

The sidebar looks roughly like:

```
User Guide
  ├─ (index)
  ├─ wallets
  │    ├─ metamask
  │    └─ abelian-mobile-wallet
  └─ staking
       ├─ qday-staking
       └─ abel-staking
```

### 3.1 Add a top-level category

Create a folder under `docs/` and add `_category_.json`:

```
docs/my-section/
  _category_.json
  hello.md
```

Example `_category_.json`:

```json
{
  "label": "My Section",
  "position": 9
}
```

Match `position` to existing sections: Overview `1`, Get Started `2`, User Guide `3`, and so on. Use a larger number for a new section.

### 3.2 Add a nested (second-level) category

Create another folder inside an existing section, again with `_category_.json`:

```
docs/guide/wallets/
  _category_.json
  metamask.mdx
```

```json
{
  "label": "Wallets",
  "position": 1,
  "collapsed": true
}
```

Third-level and deeper categories work the same way: nest folders and add `_category_.json`.

### 3.3 Moving a page changes its URL

If you move `docs/guide/metamask.mdx` to `docs/guide/wallets/metamask.mdx`, the URL becomes:

`/docs/guide/wallets/metamask`

To keep the old URL `/docs/guide/metamask`, set `slug` in the new file’s frontmatter:

```markdown
---
sidebar_position: 1
title: MetaMask Wallet
slug: /guide/metamask
---
```

Also update internal links in other docs, or keep using that `slug`.

## 4. `_category_.json`

Every folder that should appear as a **sidebar category** needs a `_category_.json`. Without it, Docusaurus uses the **folder name** as the label (e.g. `user` instead of `User Documentation`).

### 4.1 Full field reference

```json
{
  "label": "User Documentation",
  "position": 7,
  "collapsed": true,
  "collapsible": true,
  "className": "",
  "link": {
    "type": "generated-index",
    "title": "User Documentation",
    "description": "End-user documentation for QDAY — getting started, using the network, earning, and building.",
    "slug": "/user"
  }
}
```

| Field | Type | Meaning |
|---|---|---|
| `label` | string | Category name shown on the English site |
| `position` | number | Order among sibling categories/pages; smaller comes first |
| `collapsed` | boolean | Default collapsed state. `docs/start/_category_.json` uses `false` so it starts expanded |
| `collapsible` | boolean | Whether the category can collapse; default `true` |
| `className` | string | Extra CSS class; rarely needed |
| `link` | object | Page opened when the category name is clicked; see below |

### 4.2 Three ways to use `link`

**A. Omit `link` (most common)**

Clicking the category name only expands/collapses it. This is how `guide`, `start`, and `dev` work in this repo.

```json
{ "label": "User Guide", "position": 3 }
```

**B. `generated-index`: auto-generated category index**

Clicking the category name opens an index that lists child pages. This is how `user` and `technical` work.

```json
{
  "label": "User Documentation",
  "position": 7,
  "link": {
    "type": "generated-index",
    "description": "End-user documentation for QDAY — getting started, using the network, earning, and building."
  }
}
```

**C. Use `index.md` as the category landing page**

Skip `link` and put `index.md` (or `index.mdx`) in the folder instead. `docs/guide/index.md` and `docs/dev/index.md` are this pattern. `sidebar_position: 0` puts it at the top of that category.

```markdown
---
sidebar_position: 0
title: User Guide
---

# User Guide

Everyday tasks on QDay …
```

Do **not** use both `generated-index` and `index.md` as the landing page; pick one.

### 4.3 Current repo examples

| File | Notes |
|---|---|
| `docs/start/_category_.json` | `collapsed: false` — expanded by default |
| `docs/guide/_category_.json` | `label` + `position` only; landing page is `index.md` |
| `docs/dev/_category_.json` | Same as guide |
| `docs/user/_category_.json` | `generated-index` |
| `docs/technical/_category_.json` | `generated-index` |

## 5. English and Chinese (maintained separately)

The default locale is **English** (`docs/`). The second locale is **Traditional Chinese `zh-Hant`**. The two are **independent files**: editing English does not change Chinese.

### 5.1 Paths must match 1:1

| Locale | Path for the same page |
|---|---|
| English | `docs/guide/metamask.mdx` |
| Traditional Chinese | `i18n/zh-Hant/docusaurus-plugin-content-docs/current/guide/metamask.md` |

Rules:

- The **path relative to `docs/` must be the same** (`guide/metamask`).
- The **filename must match**. The extension may differ: if English is `.mdx` and the Chinese page has no components, it can be `.md` (existing guide translations in this repo do that).
- If there is no Chinese file, the Chinese site **falls back to English**. Nothing breaks.
- Other sections work the same way: replace `guide` with `start` / `migration` / `dev` / `user`, etc.

Mirror nested folders too, for example:

```
docs/guide/wallets/metamask.mdx
i18n/zh-Hant/docusaurus-plugin-content-docs/current/guide/wallets/metamask.md
```

### 5.2 Translating category labels via `_category_.json`

The English category name lives in `docs/<path>/_category_.json` as `label`.

For Chinese, put another `_category_.json` in the matching i18n folder and override only the fields you translate:

```
i18n/zh-Hant/docusaurus-plugin-content-docs/current/guide/wallets/_category_.json
```

```json
{
  "label": "錢包"
}
```

Behavior such as `position` and `collapsed` comes from the English file under `docs/`. The Chinese copy usually only changes `label` (and `link.description` if you use `generated-index`).

You can also edit keys in `i18n/zh-Hant/docusaurus-plugin-content-docs/current.json` (extracted by `npm run write-translations -- --locale zh-Hant`):

```json
"sidebar.tutorialSidebar.category.User Guide": {
  "message": "使用指南",
  "description": "The label for category 'User Guide' in sidebar 'tutorialSidebar'"
}
```

Prefer the **`_category_.json` under the i18n folder**. It is easier to see, and it is less likely to clash with auto-extracted keys.

### 5.3 Checklist for a bilingual page

1. English: `docs/<section>/[subdir/]page.md` (or `.mdx`)
2. Chinese: `i18n/zh-Hant/docusaurus-plugin-content-docs/current/<section>/[subdir/]page.md`
3. If this is a new category: English `_category_.json` plus a Chinese `_category_.json` (translated `label`)
4. Preview locally:

```bash
npm start                 # English at http://localhost:3000
npm start -- --locale zh-Hant
```

The locale dropdown in the top-right switches languages. Chinese URLs are prefixed with `/zh-Hant/docs/...`.

## 6. `.md` vs `.mdx`

| Type | When to use |
|---|---|
| `.md` | Plain docs. Use this for most pages |
| `.mdx` | When you `import` a React component, e.g. one-click add-network or faucet |

`.mdx` example (from `docs/start/add-network.mdx`):

```mdx
---
sidebar_position: 1
title: Add QDay2 to your wallet
---

import AddNetworkButton from '@site/src/components/QDay/AddNetworkButton';

# Add QDay2 to your wallet

<AddNetworkButton network="qday2" />
```

Widgets live in `src/components/QDay/`. If the Chinese page needs the same button, make that file `.mdx` too and use the same `import`.

## 7. Links, images, and callouts

### 7.1 Internal links

Use the docs route, not a repo-relative path:

```markdown
[Migration guide](/docs/migration/overview)
[Add network](/docs/start/add-network)
```

Same-folder relative links also work: `[MetaMask](metamask)`.

### 7.2 Static assets (images and other files)

Docusaurus copies everything under `static/` to the **site root**. The URL is the path after `static/`, starting with `/`.

| File on disk | URL in Markdown / the browser |
|---|---|
| `static/qday/metamask/chrome-metamask-install-en.png` | `/qday/metamask/chrome-metamask-install-en.png` |
| `static/abelian/welcome.png` | `/abelian/welcome.png` |
| `static/abel-bridge-v3/01-authorize-wallet.png` | `/abel-bridge-v3/01-authorize-wallet.png` |
| `static/img/logo.svg` | `/img/logo.svg` |
| `static/files/whitepaper.pdf` | `/files/whitepaper.pdf` |

**Where to put new files**

| Kind | Put it here | Example URL |
|---|---|---|
| Guide screenshots | `static/qday/<topic>/` | `/qday/metamask/foo.png` |
| Abelian Wallet screenshots | `static/abelian/` | `/abelian/welcome.png` |
| Bridge screenshots | `static/abel-bridge-v3/` | `/abel-bridge-v3/01-authorize-wallet.png` |
| Site chrome (logo, favicon) | `static/img/` | `/img/logo.svg` |
| Other downloads (PDF, zip) | `static/files/` (create if needed) | `/files/name.pdf` |

Do **not** put images next to the `.md` file under `docs/`. English and Chinese pages would each need a copy, and existing docs all use `static/`.

**Markdown**

```markdown
![Install MetaMask](/qday/metamask/chrome-metamask-install-en.png)
```

Optional size (HTML is allowed in Markdown):

```html
<img src="/qday/swap/swap_en.png" alt="QDAY Swap" width="720" />
```

**MDX / React** uses the same public URL:

```jsx
<img src="/qday/metamask/import-tokens1.png" alt="Import USD8" />
```

To import a file as a module (SVGs in components, etc.):

```tsx
import Logo from '@site/static/img/logo.svg';
```

**English vs Chinese screenshots**

Assets are **not** translated by locale folder. Both languages share `static/`. Use different filenames when the UI is localized:

```markdown
<!-- docs/guide/swap.mdx -->
![QDAY Swap](/qday/swap/swap_en.png)

<!-- i18n/.../guide/swap.md -->
![QDAY Swap 兌換](/qday/swap/swap.png)
```

Existing pattern: English often has an `_en` suffix (`swap_en.png`, `chrome-metamask-install-en.png`); Chinese uses the unsuffixed name or `_zh` (`portal-2-zh.png`). If the screenshot is language-neutral, both pages can point at the same file.

**Other static files**

```markdown
[Download the whitepaper](/files/whitepaper.pdf)
[Open the diagram](/qday/QDay_1.4_PSQ_Plan.png)
```

Any file type works (`.png` `.jpg` `.svg` `.gif` `.webp` `.pdf` `.mp4` …) as long as it lives under `static/`.

**Naming and size**

- Lowercase kebab-case or the existing numbered style (`01-authorize-wallet.png`).
- Keep screenshots reasonably small (compress PNGs; prefer WebP for large UI captures if needed).
- After adding files, `npm start` and open the `/...` URL directly to confirm they load.

## 8. FAQ

**The sidebar shows a folder name (`user`, `guide`) instead of a proper title.**  
That folder is missing `_category_.json`, or `label` is not set.

**The image is broken (404).**  
The Markdown URL must match the path after `static/`. `static/qday/foo.png` is `/qday/foo.png`, not `/img/foo.png` and not `qday/foo.png` (missing the leading `/`). Do not put screenshots under `docs/`.

**I added a Chinese file but the Chinese site still shows English.**  
The path does not match `docs/`, or the filename differs. The Chinese root must be `i18n/zh-Hant/docusaurus-plugin-content-docs/current/`.

**I edited English and Chinese did not change.**  
Expected. They are independent files; update both.

**I created a nested folder but the sidebar has no group.**  
Confirm the subfolder has `_category_.json` and at least one doc (empty folders do not appear). Restart `npm start` and check again.

**Do I need to edit `sidebars.ts`?**  
Usually no. Only change it if you want to stop autogenerating from the filesystem and list every item by hand.

**What if the JSON is invalid?**  
A malformed `_category_.json` or `data/updates.json` fails the build. Do not leave a trailing comma after the last item. Validate the JSON, or open a PR so CI can catch it (`.github/workflows/ci.yml`).

## 9. Local preview and publish

```bash
npm install
npm start              # http://localhost:3000
npm run build          # production build; broken links are warned in the log
```

Push to `main` and GitHub Actions deploys to Cloudflare Pages. Changes usually go live in a few minutes.
